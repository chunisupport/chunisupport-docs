# お知らせの書き方

お知らせは `src/content/announcements/` に Markdown（`.md`）または MDX（`.mdx`）ファイルとして追加します。追加したファイルは、お知らせ一覧、個別ページ、`/announcements.json` のフィードに反映されます。

## 追加手順

1. `src/content/announcements/` に `YYYY-MM-DD.md` 形式のファイルを作成します。同じ日に複数件追加する場合は、2件目以降を `YYYY-MM-DD-slug.md` 形式にします。
2. ファイルの先頭に、次の frontmatter を記述します。
3. frontmatter の後に、お知らせの本文を Markdown で記述します。
4. `npm run build` を実行し、入力内容と生成結果を確認します。

ファイル名は公開 URL の一部になります。たとえば、`2026-08-11.md` の公開 URL は `/announcements/2026-08-11/`、`2026-08-11-maintenance.md` は `/announcements/2026-08-11-maintenance/` です。`slug` には内容を表す短い英小文字・数字・ハイフンを使用します。

## 記述例

```md
---
title: 新機能を公開しました
summary: プレイヤーデータを比較できる新機能を公開しました。
publishedAt: 2026-08-12
category: update
---

プレイヤーデータを比較できるようになりました。

詳しい使い方は[ヘルプ](/help/)をご覧ください。
```

## frontmatter

| 項目 | 必須 | 内容 |
| --- | --- | --- |
| `title` | はい | お知らせのタイトル。一覧、個別ページ、フィードに表示されます。 |
| `summary` | はい | 内容の短い要約。一覧とフィードに表示されます。本文を読まなくても要点が分かる一文にします。 |
| `publishedAt` | はい | 公開日。`YYYY-MM-DD` 形式で記述します。 |
| `category` | はい | 下表のいずれかを指定します。 |

`category` に指定できる値は次のとおりです。

| 値 | 表示名 | 用途 |
| --- | --- | --- |
| `important` | 重要 | 障害、セキュリティ、利用者の対応が必要な変更など |
| `update` | アップデート | 新機能、機能改善、仕様変更など |
| `maintenance` | メンテナンス | メンテナンスの予定、開始、終了など |
| `other` | その他 | 上記に該当しない案内 |

値を省略したり、表にない値を指定したりするとビルドに失敗します。タイトルや要約に `:`、`#` など YAML で特別な意味を持つ文字を含める場合は、値全体を引用符で囲んでください。

## 本文

frontmatter の後には通常の Markdown を記述できます。見出し、箇条書き、リンク、コードブロックなどを利用できます。サイト内へのリンクは `/help/` のようにルート相対パスで記述します。

一覧とフィードには本文が含まれないため、重要な要点は `summary` にも記載してください。

## 公開前の確認

- ファイル名が既存のお知らせと重複していない
- `title` と `summary` だけでも内容が理解できる
- `publishedAt` が意図した日付になっている
- `category` が用途に合っている
- 本文中のリンクが正しい
- `npm run build` が成功する

お知らせには予約公開の仕組みがありません。`publishedAt` に未来の日付を指定しても、デプロイされるとすぐに表示されます。
